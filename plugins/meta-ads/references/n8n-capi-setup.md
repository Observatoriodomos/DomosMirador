# n8n CAPI setup — Octorate webhook → Meta main pixel

Adds CAPI Purchase events to the **main pixel** (`458979157007770` Domos Mirador Pixel Principal) from your existing Octorate-booking n8n workflow.

This is **separate from** Octorate's native CAPI (which fires to `OctorateEnginDomos` 1140308951186601, per `octorate-capi-wiring.md`). Both run in parallel — both use the Octorate booking ID as `event_id` so Meta dedups across the two pixels.

## Prerequisites

- n8n workflow that already receives the Octorate booking webhook (you confirmed this exists).
- Meta access token from `octorate-capi-wiring.md` step A1, stored as an **n8n credential** or an **n8n environment variable** named `META_ACCESS_TOKEN`. **Do not paste it directly into nodes.**
- You know what fields the Octorate webhook payload contains — open one historical execution in n8n and check the JSON shape on the trigger node. Field names below assume Octorate's standard payload; adjust if yours differs.

## Two nodes to add

Insert these **after** your existing Octorate webhook trigger, in parallel with whatever else you do with the booking (don't block your main flow on CAPI — use a fork).

### Node 1 — Code (JavaScript): build the CAPI payload

```javascript
const crypto = require('crypto');

function sha256Lower(value) {
  return crypto.createHash('sha256')
    .update(String(value).trim().toLowerCase())
    .digest('hex');
}

const booking = $input.first().json;

// IMPORTANT: adjust these field paths to match your Octorate webhook payload.
// Open a past execution in n8n to see exact names.
const bookingId    = booking.id ?? booking.booking_id ?? booking.reference;
const guestEmail   = booking.guest_email ?? booking.customer?.email;
const guestPhone   = booking.guest_phone ?? booking.customer?.phone;
const totalAmount  = booking.total ?? booking.amount_total ?? booking.price;
const currency     = booking.currency ?? 'USD';
const roomTypeId   = booking.room_type_id ?? booking.room?.id ?? 'unknown';
const nights       = booking.nights ?? booking.length_of_stay ?? 1;
const confirmUrl   = booking.confirmation_url ?? 'https://engine.octorate.com/';

// Build user_data — every field you can supply lifts EMQ.
const user_data = {};
if (guestEmail) user_data.em = [sha256Lower(guestEmail)];
if (guestPhone) {
  const digits = String(guestPhone).replace(/\D/g, '');
  if (digits) user_data.ph = [sha256Lower(digits)];
}
if (booking.client_ip) user_data.client_ip_address = booking.client_ip;
if (booking.client_ua) user_data.client_user_agent = booking.client_ua;
// fbc/fbp are *not* available from a server-only webhook — they live in
// browser cookies. If you can capture them on the Octorate page and pass
// them through, do so here.

return {
  json: {
    data: [
      {
        event_name: 'Purchase',
        event_time: Math.floor(Date.now() / 1000),
        event_id: String(bookingId),                  // dedup key
        action_source: 'website',
        event_source_url: confirmUrl,
        user_data,
        custom_data: {
          currency,
          value: parseFloat(totalAmount),
          content_ids: [String(roomTypeId)],
          content_type: 'product',
          contents: [{ id: String(roomTypeId), quantity: parseInt(nights, 10) }],
          num_items: parseInt(nights, 10),
          order_id: String(bookingId),
        },
      },
    ],
  },
};
```

### Node 2 — HTTP Request: POST to Meta

| Field | Value |
|---|---|
| Method | `POST` |
| URL | `https://graph.facebook.com/v21.0/458979157007770/events` |
| Authentication | None (token goes in query) |
| Send Query Parameters | ✅ On |
| Query Params | `access_token` = `{{ $env.META_ACCESS_TOKEN }}` |
| Send Body | ✅ On |
| Body Content Type | JSON |
| Specify Body | Using JSON |
| JSON Body | `{{ JSON.stringify($json) }}` |
| Response → Include Response Headers and Status | ✅ (for the verification step) |

### Optional Node 3 — log failures

Add an **IF** node after Node 2: condition `{{ $json.fbtrace_id }}` is set → that's an error response. Route to a logger/Slack so you know if Meta rejected events.

## Common mistakes

- **Pasting the token in the node JSON instead of using `$env.META_ACCESS_TOKEN`** — leaks the token in workflow exports.
- **Setting `event_id` to a UUID generated by n8n instead of the Octorate booking ID** — dedup with Octorate's own CAPI breaks; Meta counts each booking twice.
- **Hashing fbc/fbp** — these are *not* hashed. Plain copy from the cookies.
- **Sending `currency: 'usd'` lowercase** — Meta accepts it but flags it; use `'USD'`.
- **Forgetting `action_source`** — events get downranked.

## When you also wire Leads

For the WhatsApp / inquiry flow (not booking), repeat the same pattern in your Lia/Kommo workflow:

- `event_name: 'Lead'`
- `event_id`: Kommo lead ID (or whatever stable identifier you have)
- `custom_data.content_category`: `'whatsapp'` / `'form'` / `'phone'`
- POST to the same main pixel endpoint.
